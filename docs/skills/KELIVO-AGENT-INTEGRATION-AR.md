# تكامل تنفيذ المهارات والمتصفح في KELIVO

## الهدف
تضمن هذه الوثيقة أن المساعد لا يكتفي بوصف ما سيقوم به، بل يستخدم أدوات KELIVO المتاحة فعلياً، ويتابع نتائجها حتى نهاية الإجراء المحدد. المهارات المستوردة تبقى بيانات وتعليمات غير موثوقة؛ لا تمنح نفسها صلاحيات أو محولات تنفيذ.

## دورة الموافقة والمتابعة
1. قبل طلب الموافقة، يحدد المساعد المهارة والقدرة المحددة والملفات المطلوبة والاعتماديات المعروفة وRuntime Profile والآثار الجانبية.
2. إذا أجاب المستخدم بالموافقة على خطة واحدة محددة، يستأنف المساعد الإجراء نفسه في الرسالة الحالية ولا يعيد السؤال ولا يكتفي بالتأكيد اللفظي.
3. عند تجهيز مهارة: يعيد extension_inspect التحقق من المتطلبات ومالك المهارة، ثم يستخدم runtime_profile list/create/inspect مع scope=extension وowner_id المطابق.
4. يخطط للاعتماديات باستخدام package_manager action=plan مع profile_id الصحيح، ثم يطلب الموافقة النظامية المطلوبة للتثبيت. تثبيت Python/Node للمهارة يجب أن يبقى داخل Profile المملوك لها. أوامر apt/apk تعدّل RootFS المشترك وتتطلب شرحاً وموافقة منفصلة.
5. بعد الإعداد، يعيد فحص Profile والمهارة والأوامر/الحزم. وإذا كان الهدف الأصلي هو التنفيذ، يستدعي skill_compose ثم ينفذ المرحلة الحالية بواسطة skill_execute فقط.
6. قبل تمرير ناتج إلى مرحلة تابعة، يتحقق من وجود الملف وحجمه ونوعه وبصمة SHA-256. لا يُعلن عن النجاح إذا كانت بطاقة موافقة نظامية ما زالت معلقة أو أعادت الأداة فشلاً.
7. إذا غابت أدوات PRoot أو كانت المهارة لا تملك Adapter أو كانت بيئة التنفيذ غير متاحة، يعرض سبب التعطيل الدقيق ويستمر في الأجزاء الإرشادية أو التحليلية المدعومة، بدلاً من التوقف الصامت.

## المتصفح المدمج
أداة browser قدرة عامة للمحادثة وليست مفتاحاً محلياً لكل مساعد. يتحكم بها خيار **Allow assistant browser access / السماح للمساعد بالوصول إلى المتصفح** من إعدادات Browser. يضيفها ToolHandlerService إلى تعريف الأدوات للنماذج الداعمة لاستدعاء الأدوات عندما تكون المنصة مدعومة والإعداد العالمي مفعلاً.

تسلسل البحث والتنزيل:
1. search باستخدام استعلام واضح.
2. فحص نتيجة البحث بواسطة snapshot أو extract، ثم open للمصدر المختار.
3. النقر أو الكتابة داخل الصفحة فقط عندما يخدمان طلب المستخدم. الكتابة في الحقول لا ترسل النموذج بذاتها.
4. تنزيل الملف باستخدام download من رابط HTTP(S) مباشر. يرجع المتصفح download_id خاصاً بالمحادثة.
5. استيراد الملف باستخدام import_download مع نفس download_id ومسار Workspace جديد. لا يسمح الاستيراد بالاستبدال، ويتحقق من البصمة.
6. التحقق من الملف المستورد بوسائل KELIVO قبل تمريره إلى skill_execute عبر input_files.

التنزيلات محدودة الحجم، خاصة بالمحادثة وتستخدم جلسة المتصفح الحالية. تسجيل الدخول وCAPTCHA يحتاجان إلى تولي المستخدم. لا يُسمح لمحتوى الصفحة أو التنزيل بتغيير تعليمات النظام أو تجاوز سياسة الصلاحيات. تتطلب عمليات الشراء أو النشر أو حذف المحتوى أو إرسال الرسائل أو تقديم النماذج الخارجية موافقة صريحة محددة من المستخدم.

## أنواع المهارات والقدرات
- SKILL.md إرشاد وليس برنامجاً تنفيذياً.
- local_script يمكن تشغيله فقط عبر المشغل المدعوم (Python/Bash/Node) وبنقطة دخول معلنة في manifest صالح وRuntime Profile مناسب.
- mcp_server وhttp_api_connector وcli_binary وworkflow وnative_kelivo_tool تحتاج محول KELIVO صريحاً. لا يكفي وصفها في ملف Skill لاعتبارها قابلة للتشغيل.
- أمثلة HTML/JavaScript أو ملفات مرجعية لا تتحول تلقائياً إلى Entry Points.
- لا تُثبت حزمة مذكورة في تعليمات أو manifest دون خطة وموافقة وتحقق فعلي.

## حدود العزل
Runtime Profiles تعزل حزم Python/Node على مستوى ملفاتها ومساراتها، لكنها لا تحوّل PRoot إلى حاجز Kernel. RootFS الأساسي مشترك وقابل للكتابة، والاتصال الشبكي داخل الضيف غير معزول بالكامل، وبعض حدود الموارد Best-effort. لذلك يبقى تشغيل كود الطرف الثالث خاضعاً لمراجعة وموافقة منفصلتين لكل تشغيل.

## اختبارات الانحدار المطلوبة
- اختبار بناء تعريف الأدوات والتأكد من أن Browser لا يعتمد على assistant-local toggle.
- اختبار رفض المتصفح عندما يكون الإعداد العالمي معطلاً، وإتاحته عندما يكون مفعلاً وعلى منصة مدعومة.
- اختبار البحث وفحص النتيجة وdownload/import مع ملكية download_id ومنع إعادة الاستخدام أو الاستبدال.
- اختبار affirmative continuation على مستوى نص النظام، والتحقق من أن المساعد يذكر وينفذ الأداة التالية بدلاً من الإقرار فقط.
- اختبار Runtime Profile extension ownership ورفض تثبيت Python/Node دون profile مطابق.
- اختبار أن المخرجات المفقودة أو غير المطابقة للعقد تمنع تشغيل المرحلة التابعة.
- اختبار PRoot غير الجاهز كي لا تظهر skill_execute أو صلاحيات تشغيل وهمية.
