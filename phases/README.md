## Working rules

1. Read the master plan and every prior phase record before changing code.
2. Implement only the active phase. Do not pull future-phase installers, video engines or providers into the core prematurely.
3. Do not regress the current Android app, chat, assistants, model providers, workspaces, PRoot or MCP. The user has explicitly waived preservation of local test/user data during this development project; do not add migrations or backup complexity solely to preserve data across development reinstalls. Keep the database schema internally valid.
4. Every new extension remains optional and independently installable/removable. Do not bundle a default video skill, engine, model provider or production library.
5. Every phase must include source changes, tests, a report, known limitations and explicit acceptance criteria.
6. Keep the complete project tree and original paths when creating delivery ZIPs.
