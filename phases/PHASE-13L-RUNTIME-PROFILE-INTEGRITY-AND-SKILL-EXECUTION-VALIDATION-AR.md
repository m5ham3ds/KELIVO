# PHASE13L — Runtime Profile Integrity & Skill Execution Validation

## نطاق النسخة

هذه الدفعة تضيف أساساً موثوقاً لمستويات الجاهزية وأدلة المتطلبات، وتصلح اكتشاف المتطلبات الكاذب لكلمة `make`. وهي لا تدّعي إكمال فاحص Runtime Profile ذاتي أو اختبار Android E2E؛ يجب أن تبقى هذه البنود غير مكتملة حتى تُنفّذ من داخل التطبيق وتُحفظ أدلتها فعلياً.

## ما تغيّر

1. **تحليل المتطلبات من مصادر قابلة للإثبات**
   - لا يُستنتج اسم أمر من نص Markdown العادي؛ تفحص المقاطع البرمجية والأسطر الموجودة داخل أقسام متطلبات صريحة.
   - كلمة `make` لا تصبح GNU Make لمجرد ورودها في جملة مثل `make a reel` أو `make sure`. تُقبل فقط صياغة أداة واضحة مثل `GNU Make` أو اسم أمر داخل سياق تنفيذي.
   - يرفق التقرير مسار المصدر ورقم السطر حيث أمكن.
   - تُستنتج المفسرات من نقاط الدخول المعلنة، وليس من أي ملف `.js` أو `.py` عشوائي.

2. **فصل أنواع الجاهزية**
   - `Ready for Guidance`: يمكن الاستفادة من تعليمات المهارة، ولا يثبت ذلك تشغيل أي سكريبت.
   - `Ready for Execution`: توجد قدرة منفردة أو أكثر اجتازت تحققاً موثقاً داخل Profile تابع للمهارة؛ التنفيذ يظل خاضعاً لصلاحيات وموافقة التشغيل المعتادة.
   - `Fully Ready`: اجتازت كل القدرات الإلزامية الاختبارات ولديها أدلة، مع وجود تحقق إجمالي ناجح للمهارة.
   - تحتفظ بيانات القدرة بمعرّفها ونقاط دخولها حتى ترتبط نتائج الاختبار بالقدرة الصحيحة.

3. **حماية الاستيراد من استنتاج سكريبتات أمثلة المتصفح**
   - تظل ملفات `examples/`, `demo/`, `samples/`, `tests/`, `fixtures/` و`assets/` محفوظة كموارد.
   - لا تُسجّل هذه الملفات تلقائياً كنقاط تشغيل لمجرد امتدادها `.js` أو `.py`.

4. **الواجهة وسياسة المساعد**
   - تعرض تفاصيل المهارة مستوى الجاهزية بدلاً من اختزال حالات التوجيه والتنفيذ والاكتمال في شارة واحدة.
   - لا يسمح توجيه المساعد بوصف قدرة غير مختبرة على أنها تعمل، ولا تُعد لقطة الجاهزية المحفوظة دليلاً على أن البيئة لم تتغير.

5. **CI مركّز**
   - أضيفت اختبارات مركزة لمحلل المتطلبات، وسجل الاستيراد، ومحرك مستويات الجاهزية.
   - لا تُعاد اختبارات المراحل التاريخية 13A–13D إلى مسار CI.

## نتيجة تدقيق المهارات الست المرفقة

| المهارة | الملفات القابلة للتنفيذ التي وُجدت في الأرشيف | ملاحظة الاعتماديات |
|---|---|---|
| `ig-profile` | لا توجد سكريبتات؛ ملف تعليمات و`rubric.json` | إرشادية، لا تثبت وجود أدوات خارجية |
| `ig-viral` | `swipe.py` | Python Standard Library؛ `yt-dlp` مسار اختياري للبحث عن Shorts وليس شرطاً لكل استخدام |
| `ig-reel` | `beats.py`, `hookscore.py` | السكريبتات المعاينة تعتمد على Python Standard Library |
| `character-visual-director` | أمثلة JavaScript/HTML داخل `examples/` | أمثلة Canvas/DOM للمتصفح وليست نقاط Node CLI تلقائية؛ تتضمن ملفات خطوط وصورة مرجعية |
| `animation-director` | لا توجد سكريبتات؛ ملف تعليمات فقط | توجيه إخراجي، ولا يثبت وحده توفر محرك رندر |
| `arabian-motion-video-director` | لا توجد سكريبتات مساعدة مرفقة رغم الإشارة إليها | حزمة ناقصة الموارد؛ راجع القائمة أدناه |

### الملفات المشار إليها ولكنها غير موجودة في `arabian-motion-video-director.zip`

- `scripts/preflight.sh`
- `scripts/preview.mjs`
- `scripts/create_env.sh`
- `scripts/normalize_env.py`
- `references/arabic-rtl-production.md`
- `scripts/fetch_pixabay.mjs`
- `scripts/fetch_freesound.mjs`

يجب ألا يعلن KELIVO اكتمال هذه المهارة التنفيذية قبل توفير هذه الملفات أو تعديل تعليماتها بموافقة المستخدم. لم تُنشأ ملفات بديلة تخميناً.

## ما لم يُنفّذ بعد — لا يُعد منجزاً في PHASE13L.0

- فحص الإصدارات والحزم **داخل** Runtime Profile المملوك للمهارة؛ فحص Base PRoot وحده لا يكفي.
- تشغيل Self-Test آمن محدد لكل قدرة وحفظ نتيجة الخروج ومخرجاته وSHA-256 وربطها بمعرّف Profile ومصدر المهارة.
- توليد/تحديث سجلات `runtimeProfileVerification` و`capabilityResults` من دليل التنفيذ الحقيقي، لا من إدخال شكلي أو من رد المساعد.
- عزل اعتماديات النظام المشتركة وSnapshots وLockfiles (نطاق PHASE13M).
- فرض صلاحيات Sandbox على مستوى محرك التنفيذ خارج قيود PRoot الحالية (نطاق PHASE13N).
- شاشة Skill Doctor واختبارات Android E2E على جهاز حقيقي (نطاق PHASE13O/13P).

## حدود الأمان

اكتشاف المتطلبات في هذه المرحلة قراءة فقط. لم تُثبت أي حزمة، ولم يُشغّل أي سكريبت من المهارات الست، ولم يتم الاتصال بـ APIs خارجية أو تمرير أسرار. تنفيذ سكريبتات المهارات يظل من خلال منفذ `SkillExecutor` الحالي، وضمن Skill-owned Runtime Profile ومراجعة الأذونات وموافقة كل تشغيل.

تظل PRoot بيئة مساعدة بعزل محدود، وليست عزلاً على مستوى نواة Linux. حدود CPU والذاكرة والعمليات best-effort، كما أن حد القرص/المخرجات ليس quota مستمراً أثناء التشغيل. لا يجوز وصف هذه الحدود بأنها حماية نظام تشغيل صلبة.
