# Phase 13H — تصحيح تصنيف مرفقات ZIP وتوجيه أدوات الأرشيف

**الحالة:** تنفيذ مصدري مكتمل، والقبول النهائي ينتظر Flutter CI وتجربة Android الفعلية.

## المشكلة المرصودة

أظهرت صور الهاتف أن المستخدم يرفق `animation-director.zip` أو `character-visual-director.zip`، لكن نموذج الأدوات يستدعي `list_dir` على مسار الملف `/chat/attachments/<name>.zip` ثم تظهر رسالة `directory not found`. وفي بعض الحالات يواصل النموذج محاولة `read_file` وكأن المرفق ملف نصي عادي.

هذا المسار غير صحيح: ZIP ملف أرشيف، وليس مجلداً ولا نصاً قابلاً للإدراج مباشرة في سياق النموذج. ويجب أن تتم عملية استيراد Skill ZIP عبر `extension_install` مباشرة، أو فحص محتوياته بأداة الأرشيف دون فكّه عشوائياً.

## تغييرات التنفيذ

1. **منع فك الأرشيف كنص:** يرفض `DocumentTextExtractor` استخراج ZIP و7z وRAR وTAR وGZip وBZip2 وXZ وAPK وAAB وJAR وEPUB كنص مضمّن. كما يكشف ترويسة ZIP حتى عندما يتغير الامتداد أو تكون بداية الملف صالحة لـUTF-8 ولا تحتوي بايت NUL.
2. **الحفاظ على DOCX:** يبقى DOCX على مسار استخراج `word/document.xml` المخصص قبل قواعد منع الأرشيف؛ لأن DOCX حاوية ZIP لكنها مستند مدعوم.
3. **تصحيح MIME:** يتعرف منتقي المحادثة ومحلل مرفقات المستند على `.zip` وبقية الامتدادات المضغوطة حتى عندما يبلغ موفر الملفات عن `application/octet-stream`.
4. **تعافٍ من استدعاء الأداة الخاطئ:** إذا استدعى النموذج `list_dir` على مسار ينتهي بـ`.zip`، تعيد `WorkspaceToolsService` بيان الأرشيف بدلاً من محاولة سرد المجلد. يحتوي الناتج على أسماء الملفات وأحجامها وإرشاد واضح إلى `read_file` مع `archive_entry`، أو `extension_install` عند تثبيت Skill.
5. **خطأ مرفق مفقود واضح:** إذا لم يوجد الأرشيف في مساحة المحادثة، يعيد النظام `zip_attachment_missing` مع توجيه إلى إعادة إرفاق الملف أو انتظار اكتمال مزامنة المرفق، بدلاً من رسالة `directory not found` المضللة.
6. **استمرار حماية الأرشيف:** لا تزال قراءة ZIP تستخدم حدود حجم الأرشيف والعدد والحجم الموسّع وحجم العضو، وترفض المسارات غير الآمنة داخل الأرشيف.
7. **التوجيه في رسالة المستخدم:** يستمر تضمين المسار المحلي للمرفق في تعليمات مساحة العمل، مع حظر `list_dir` عليه وتوجيه التثبيت مباشرة إلى `extension_install`.

## اختبارات الانحدار المضافة

- ZIP معروف الامتداد مع MIME عام لا يدخل مستخرج النصوص.
- منشئ الرسالة يوجّه Skill ZIP إلى مسار مساحة العمل مع `extension_install` ولا يحقن بايتات الأرشيف في نص الطلب.
- ترويسة ZIP مع امتداد مختلف لا تدخل مستخرج النصوص.
- DOCX يحتفظ بمسار الاستخراج المخصص.
- استعادة MIME الصحيح لأرشيف ZIP الذي أبلغ عنه Android كـ`application/octet-stream`.
- مزامنة ZIP إلى `/chat/attachments/animation-director.zip` والتحقق من وجود الملف وبقاء بايتاته.
- `list_dir` على ZIP يعيد manifest، وليس خطأ مجلداً مفقوداً.
- ملف ZIP المفقود يعيد `zip_attachment_missing` ورسالة مزامنة مفيدة.
- اختبارات HostFileTools الحالية لقراءة بيان الأرشيف وأعضاء النصوص، واختبار استيراد Skill ZIP عبر `/chat`.

## نطاق التغيير وما لم يتغير

- لا تُضاف أي حزمة أو أداة جديدة؛ يستخدم التنفيذ حزمة `archive` الموجودة بالفعل.
- لا يتم فك أرشيفات ZIP عشوائياً إلى مسارات المستخدم.
- لا تتغير سياسة استقلال Skills عن Skill Packs.
- لا يعاد تشغيل اختبارات 13A–13D المعتمدة.
- لا يتم تغيير طريقة قراءة TXT/MD أو ملفات النصوص العادية.

## نتائج الفحص المتاحة محلياً

نجح `bash .github/scripts/preflight_phase13h_tests.sh` وتحققت 19 نقطة بنيوية، ونجح فحص توصيل المرحلة إلى GitHub Actions، ونجح فحص `bash -n` للـrunner. لم تتوفر Flutter أو Dart في بيئة العمل الحالية؛ لذلك لم يتم تشغيل `flutter test` أو `dart format` أو `dart analyze` محلياً، ولم يتم بناء APK. أُدرجت اختبارات المرحلة المركزة في `run_phase13h_tests.sh` ضمن GitHub Actions لتنفذ في بيئة Flutter الفعلية.

## معايير القبول النهائية

1. نجاح اختبارات Phase 13H المركزة في GitHub Actions.
2. نجاح بقية CI الحالي وبناء Android ARM64 دون إعادة تشغيل مجموعات 13A–13D.
3. على الهاتف: رفع Skill ZIP وطلب تثبيته يؤدي إلى استدعاء `extension_install` على المسار الصحيح، دون `list_dir` أو محاولة فك الأرشيف كنص.
4. على الهاتف: فحص ZIP دون تثبيته يعرض manifest، ثم يسمح بقراءة `SKILL.md` أو مرجع محدد باستخدام `archive_entry`.
5. إذا تعذر العثور على الملف، تظهر رسالة تفيد بفشل مزامنة/غياب مرفق ZIP مع إمكانية إعادة إرفاقه.
