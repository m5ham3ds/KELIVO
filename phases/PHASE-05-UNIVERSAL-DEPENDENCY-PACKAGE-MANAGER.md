# Phase 5 — Universal Dependency & Package Manager

## الهدف

تمكين الوكيل من اكتشاف مدير الحزم الملائم وإدارة تبعيات الأدوات والمهارات من المحادثة، بدلاً من حصر المستخدم في قائمة أسماء أدوات ثابتة. يبقى مدير الحزم طبقة قابلة للتوسعة عبر Adapters، ولا يُسمح له بتنفيذ أوامر اعتباطية أو تثبيت مصادر غير موثوقة.

## النطاق المعتمد لهذه المرحلة

### 1. Package Manager Adapters

العقد `PackageManagerAdapter` يفصل الخدمة العامة عن أوامر كل مدير حزم. تشمل الموجة الأولى:

- النظام داخل PRoot: `apt` و`apk`.
- Python: `pip` و`uv` مع بيئة افتراضية مستقلة لكل نطاق.
- Node.js: `npm` و`pnpm` و`yarn` و`bun` مع مجلد تثبيت مستقل لكل نطاق.

المعمارية تسمح بإضافة Adapter لاحقاً، لكن هذه المرحلة لا تدّعي دعم Cargo أو RubyGems أو مدير Android/Gradle أو أي مصدر غير مضاف صراحةً.

### 2. اكتشاف البيئة

يفحص Kelivo التوزيعة ومعمارية التشغيل والأوامر المتاحة، ثم يختار المدير حسب نوع الاعتماد وملفات القفل الموجودة. يدعم `apt` توزيعات Debian/Ubuntu ويدعم `apk` Alpine فقط. لا يُنفّذ مدير غير متاح، ولا يجرّب مديراً آخر بصمت إذا تعذر تنفيذ الاختيار.

### 3. مصادر التبعيات

يقرأ المحلل، دون تشغيل أي ملف:

- `requirements.txt`.
- قسم `[project].dependencies` الأساسي في `pyproject.toml`.
- `dependencies` و`devDependencies` و`optionalDependencies` في `package.json`.
- عقود Kelivo الاختيارية في `SKILL.md` عبر Agent Skills `metadata`:

```yaml
metadata:
  kelivo.package-manager: uv
  kelivo.packages: "requests==2.32.3, beautifulsoup4==4.12.3"
```

لا يؤدي استيراد Skill أو معاينتها إلى تثبيت اعتمادياتها. يجب استدعاء أداة `package_manager` صراحةً، وتُطلب موافقة منفصلة قبل أي تغيير.

### 4. نسخ الإصدارات والنطاقات

تُدار الحزم ضمن `runtime` أو `project` أو `extension` أو `task`. ويُقبل `global` كاسم توافق قديم لـ `runtime`. حزم النظام `apt/apk` تظل على مستوى PRoot المشترك فقط؛ أما Python وNode فتُعزل مجلداتها بحسب النطاق والنظام البيئي.

تُرفض مراجع URL وGit وملفات الحزم المحلية وخيارات shell. عمليات `install` و`upgrade` تعتمد إصداراً دقيقاً عند تحديده. إذا كشف ملف manifest مجال إصدار غير مثبت، يُعرض التحذير وتُمنع عملية التثبيت حتى يحدد المستخدم إصداراً دقيقاً.

### 5. الأمان والموافقة

- `plan` و`check` و`list` للقراءة فقط.
- `install` و`upgrade` و`remove` و`pin` و`unpin` تتطلب موافقة المستخدم لكل استدعاء.
- تُعطّل Python source builds وNode lifecycle scripts افتراضياً. يضبط Adapter الخاص بـ Yarn كلاً من `YARN_ENABLE_SCRIPTS` (Berry) و`YARN_IGNORE_SCRIPTS` (Classic)، لأن الخيار `--ignore-scripts` ليس خياراً صالحاً في جميع إصدارات Yarn.
- لا تُقبل روابط أو أوامر shell أو نصوص تنزيل وتشغيل بعيدة كأسماء حزم.
- يتحقق النظام من وجود الأوامر بعد التثبيت عند طلب `verify_binaries`.
- يفحص توافق التوزيعة ومعمارية ARM64 ويصدر تحذيراً عند عدم التحقق.

### 6. سجل العمليات والاستعادة

يُحفظ سجل الحزم والإصدارات المثبتة والمثبتة كـ pins وسجل عمليات محدود في مخزن Kelivo الحالي دون ترحيل لقاعدة البيانات. تُكتب lockfiles لكل نطاق ونظام بيئي. قبل التغيير تُلتقط حالة الحزم المستهدفة؛ وعند الفشل يحاول المدير استعادة الإصدار السابق أو إزالة الحزمة الجديدة.

هذه آلية استعادة على مستوى الحزم التي تديرها العملية، وليست Snapshot كاملاً لنظام PRoot أو نسخة احتياطية لكل الملفات العابرة التي قد يغيرها مدير الحزم.

## التكامل مع المحادثة

الأداة المحلية `package_manager` هي واجهة الاستخدام الأساسية. تستطيع استقبال اسم حزمة أو قائمة أو manifest أو `skill_id`، وتعرض نتيجة الخطة/الفحص/التثبيت/الإزالة مع المدير والنطاق والتحذيرات وسجل التنفيذ. لا توجد صفحة تثبيت مستقلة مطلوبة لإدارة الحزم.

## معايير القبول

1. اكتشاف مدير متاح ومتوافق أو إرجاع سبب واضح لعدم الدعم.
2. قراءة manifests المدعومة وبيانات Skill دون تنفيذ محتواها.
3. رفض أسماء الحزم غير الآمنة والمصادر غير المدعومة.
4. عرض خطة بلا آثار جانبية قبل التنفيذ.
5. عدم تنفيذ أي عملية تعديل من دون موافقة المستخدم.
6. عزل نطاقات Python وNode، وحصر apt/apk في PRoot runtime.
7. التحقق من الحالة والإصدار بعد التثبيت، وتسجيل العملية والفشل.
8. إمكانية إزالة الحزمة من النطاق نفسه، مع الاحتفاظ بسجل العملية.
9. اجتياز Android-only audit والاختبارات المركزة وبناء Android ARM64 Release عبر GitHub Actions.

## حدود مقصودة

لا تتضمن Phase 5 محرك تنفيذ Skills أو نقل Artifacts بينها (Phase 4 acceptance gap)، ولا عزل Runtime Profiles الكامل وإدارة العمليات الطويلة (Phase 6)، ولا Video Engine Adapters (Phase 7). كما لا تضيف دعم مديري حزم خارج القائمة المذكورة حتى يُكتب Adapter واختبار توافق خاص به.
