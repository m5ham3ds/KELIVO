## السبب الجذري

كان `GitHubSkillRef.tryParse()` يستدعي `Uri.tryParse(text)` قبل فحص مسار الرابط الخام. محلل `Uri` يستطيع تطبيع مقاطع النقاط الحرفية مثل:

```text
/skills/../outside.skill
```

وبعد التطبيع لا يرى التحقق اللاحق مقطع `..` الأصلي، فيقبل مرجع GitHub رغم أن الاختبار يتوقع رفضه. لذلك كان فشل الاختبار حقيقيًا ويشير إلى فجوة في التحقق الأمني، وليس اختبارًا خاطئًا.

في نسخة المصدر المستخدمة في commit المذكور لم يكن فحص المسار الخام قبل `Uri.tryParse` موجودًا؛ لذلك لم يكن إصلاح سابق متعلق بهذه الحالة موجودًا فعليًا في هذا الـcheckpoint. هذا التصحيح يضع الحماية في محلل الروابط نفسه، قبل تطبيع URI، ضمن نسخة Skill Pack Independence التي دخلت البناء.

## الإصلاح

الملف المعدل: `lib/core/services/skills/github_skill_ref.dart`

أضيفت `_hasUnsafeRawPathSegments()` وتُستدعى قبل `Uri.tryParse()`. تقوم بفحص المسار الأصلي داخل النص، قبل أن يطبّعه محلل URI، وتكشف:

- مقاطع `.` و`..` الحرفية.
- النقاط المشفرة مثل `%2e%2e` و`%2E.`.
- الترميز المزدوج والمتعدد مثل `%252e%252e` و`%25252e%25252e` ضمن حد فك متكرر ثابت.
- الفواصل المشفرة `%2f` والشرطة العكسية `%5c`، بما فيها الحالات مزدوجة الترميز.
- محارف NUL المشفرة `%00`.
- المقاطع الفارغة الداخلية والشرطات العكسية الحرفية التي قد تُفسَّر بصورة مختلفة بين محللات URL والوسطاء.

يُرفض المسار غير الآمن قبل تحليل URI، بينما تبقى أسماء الملفات العادية ذات النقاط الداخلية والمسافات المشفرة صالحة، مثل `character..director.skill` و`my%20skill.skill`. لا تتغير دلالات روابط GitHub المدعومة `blob` و`raw` و`?ref=` للروابط السليمة.
