# PHASE 13R — موثوقية دورة تثبيت Environment Image وPresets وMedia tools

**الفرع:** main فقط؛ لا تُنشأ فروع اختبار موازية.
**الحالة قبل CI:** التعديلات والاختبارات المركزة مضافة إلى main. القبول النهائي ينتظر CI على commit الإصلاح واختبار الجهاز.

## الهدف

يجب أن تظل واجهة التثبيت وإشعار Android وعمليات المثبّت متزامنة من بداية التنزيل/التثبيت حتى اكتمال التحقق النهائي. مغادرة الصفحة لا تعني انتهاء المهمة أو فقد إمكانية العودة إليها.

## الأسباب الجذرية المرصودة

1. منع مدخل Media tools من الفتح عندما تكون خدمة التثبيت busy حتى لو كانت المهمة التي تشغلها هي مهمة Media tools نفسها.
2. جعل busy المحلي في Environment pane مدخل System image غير متاح بعد مغادرة صفحة التثبيت والعودة.
3. تشغيل فحص شامل لجميع Presets بعد تثبيت Preset واحد. كان ذلك يشمل Browser Renderer وSmoke Test طويل لا علاقة له بالحزمة المثبتة.
4. استمرار قابلية الإلغاء بعد نجاح APT/APK، ما يسمح بتسجيل الإلغاء بعد وجود الحزمة بالفعل.
5. سماح إجراء Stop في إشعار Foreground بالتأثير على مهمة دخلت بالفعل مرحلة تحقق لا يمكن التراجع عن تثبيتها.

## الإصلاح

- إعادة فتح System image وMedia tools تعرض المهمة الحية نفسها ولا تنشئ تثبيتاً ثانياً.
- أصبح فحص Preset المفرد مقتصراً على أوامر ذلك الـPreset؛ وفحص أداة Media فردية مقتصر على أوامر Media tools؛ والتثبيت الجماعي يتحقق من الأدوات الست.
- خروج مدير الحزم بنجاح هو commit point. بعده يستمر التحقق لكن تتحول المهمة إلى non-cancellable ويُزال زر الإلغاء من الواجهة وإشعار Android.
- بعد استبدال RootFS ذرياً، يتجاهل المثبّت طلبات الإلغاء المتأخرة.
- تتضمن snapshot المهمة حقل cancellable؛ لا يوقف Android الخدمة حتى تصله الحالة النهائية التي تؤكد انتهاء عملية الإلغاء أو التحقق.
- يحافظ Android Foreground Service على المهمة أثناء نافذة إنهاء الإلغاء؛ لا يُزال إشعار الخدمة لمجرد أن المستخدم ضغط Stop.

## الاختبارات

- dependency_test_runtime وenvironment_dependencies_test: targeted probe، ومنع الإلغاء أثناء تحقق الحزمة بعد commit.
- environment_presets_test: إعادة فتح System image وMedia tools أثناء استمرار نفس المهمة.
- environment_installer_test: الإلغاء المتأخر بعد استبدال RootFS الذري لا يغير الحالة الجاهزة.
- mobile_background_test: flush فوري لحقل cancellable إلى Native snapshot.
- BackgroundRuntimeTest (Robolectric): Stop لا يزيل مهمة committed، والطلب المختلط يرسل الإلغاء للمهام القابلة للإلغاء فقط.
- GitHub Actions يشغل اختبار Flutter مركز لهذه الملفات قبل بقية بوابات البناء.

## بوابة القبول

يتطلب قبول Phase 13R نجاح Flutter Analyze، والاختبارات المركزة المضافة، وAndroid JVM/Robolectric، وPhase 13P Emulator E2E، وبناء Release ARM64 ورفع Artifact.

بعد صدور APK يلزم اختبار على هاتف Android: بدء تثبيت صورة النظام أو أداة Media، الانتقال إلى تطبيق آخر وإزالة KELIVO من Recents ثم العودة للتحقق من حالة المهمة والصفحة. يجب أيضاً تجربة Stop بعد خروج APT/APK وأثناء مرحلة التحقق؛ النتيجة الصحيحة هي استمرار التحقق حتى نتيجة verified.

Force Stop أو قتل العملية أو إعادة تشغيل الجهاز خارج ضمان استمرار stream حي؛ خدمة Foreground لا تستعيد عملية Dart/HTTP حية بعد موت عملية التطبيق.
